# 文档类型模板

## 技术调研报告（可复制骨架）

技术调研报告有两个档位：**档位 A（含国内小节）** 适用于存在真实国内外对照信息量的主题（国内产业、厂商、平台落地）；**档位 B（通用）** 适用于无国内外对比需求的纯技术主题。两档的差异只在 `背景与现状` 是否设“国内”三级小节，其余结构完全相同。下面的骨架是档位 A 的完整版本。

将骨架复制到新报告；替换方括号内容，保留二级标题顺序、来源 ID 与图注格式。图片路径必须相对报告文件，且在交付时存在。正文不得出现过程性材料（结论依据对照、检查/验收清单、方法与局限、术语表）与证据标记。

### 使用约定

- `图 N：` 使用中文全角冒号；图注内同时写来源与 `[Snn]`，并在图注之外的正文引用该图号；引用处用 2–4 句说明“读这张图先看什么”。
- 每条关键结论都可从 `附录 A：主要结论与依据对照` 回溯到来源台账；关键结论优先链接原始论文、标准、上游项目、源码、公告或可复现实验。
- 校验器强制的下限（2026-10-10 结构与语言版）：`背景与现状` ≥600 汉字且 ≥8 个可定位锚点，国内小节 ≥260 汉字；`技术详解` ≥4000 汉字、≥3 个三级小节、全章 ≥2 段围栏代码块与 ≥12 个源码锚点（函数/文件）；每小节 ≥800 汉字、≥2 个不同来源、≥12 个可定位锚点（其中 ≥2 个函数或文件锚点）、≥2 处行内代码、一条 ≥3 环节的步骤序列，并答满四项（实现与接口依据/失效边界/验证条件/成本与权衡）；`总结与展望` ≥400 汉字；摘要每条 ≥40 汉字；正文不得出现 `契约`、`证据` 等 Meta 词汇与 `【C】` 式标记。历史报告保持原状态，下一次升版时按新标准重写。
- 不以总字数作为深度指标。补充结论、依据、边界、工程影响与可验证条件，而非重复背景或堆砌引文；机制小节要给出调用链、设计动因、失败模式与逐字片段（细则见 `writing-standards.md` 与 `research-methodology.md`）。
