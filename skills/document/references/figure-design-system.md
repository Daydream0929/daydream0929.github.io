# 图表设计系统（编辑级规范）

本文件是报告的图表设计语言与质检规则，适用于**手写 SVG 图**（架构图、机制图、对照矩阵等），也为 matplotlib / graphviz 生成的图提供配色与复杂度纪律。与 `figures-guide.md`（工具分工与生成流程）配套使用。

**来源与适配声明**：蒸馏自 [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)（MIT License, Copyright (c) 2025 Cathryn Lavery，v2.6，2026-10 调研）。上游工作流为 HTML-first + 脚本导出 SVG；本 skill 管线是 `md → SVG/PNG 资产 → HTML 内联`，方向相反，因此只吸收其设计语言与质检规则，不采用其模板、脚本或 HTML 导出流程。

## 1. 设计哲学

- **删除至上**。能删的节点、箭头、标签一律删掉；读者看不懂就保留，看得懂就删。图的每一笔都要挣得自己的位置。
- **复杂度预算（每图）**：主节点 ≤9、连线 ≤12、焦点色元素 ≤2、注释标签 ≤2。超了拆两图（总览 + 细节），不要缩字号硬塞。
- **图不是装饰**。一段话或一张表能说清的，不画图。图只承担三件事：形状（结构）、对比（数据）、机制（流程）。

## 2. 语义色角色（映射到房屋调色板）

颜色按**语义角色**引用，不按喜好挑色。映射到 `figstyle.PALETTE`：

| 角色 | 用途 | 房屋色 |
|------|------|--------|
| paper | 背景、节点默认填充 | `#ffffff` |
| ink | 主文字、主描边 | `#202124` |
| muted | 次级文字、默认连线 | `#5f6368` |
| soft | 标签、边界注释、sublabel | `#9aa0a6` |
| accent | 焦点（每图 ≤2 处） | `#ea4335` |
| link | 外部/API/跨边界连线 | `#4285f4` |
| good / warn | 仅承载数据语义（通过 / 门控），不做装饰 | `#34a853` / `#fbbc04` |

纪律（比色值重要）：

- **单一强调色**。架构类图的结构框一律用 ink/muted 系（白色/浅灰填充 + ink/muted 描边）；红绿黄只承载"错误/通过/门控"的数据语义，不做"这个也重要"式装饰。焦点色一多，层级就塌了。
- **对比度契约**。正文级文字 ≥4.5:1（对实际所在背景，不是对 paper）；线条、箭头、边框等非文字要素 ≥3:1；半透明色先合成再测。浅色填充上的文字要按填充色算对比度。
- **一个颜色一个角色**。`muted` 又当正文又当连线可以（约定角色内），但不为"好看"引入第三个灰。
- **矩形标签（type tag）** 用 rx=2 的小矩形 + 细描边，不做药丸形。

数据图（matplotlib）沿用 `figstyle.PALETTE` 既有语义：primary 结构、accent 错误/焦点、good 通过、warn 门控、muted 弃用——同样遵守"焦点色 ≤2"。

## 3. 文字与 CJK 排版

- **字号地板：手写 SVG 中汉字 ≥12px**。汉字在 12px 以下笔画粘连不可读；装不下就截短名字，不要缩字号。
- **逐字宽度预算**：宽字符（汉字、全角标点 `（）「」，。：`）计 1em/字；西文与半角字符计约 0.6em/字（等宽约 0.62em）。文本宽 = Σ 字宽 × 字号；盒子宽 = 文本宽 + 2×内边距（8/12/16），向上取整到 4 的倍数。**按字符逐个算，不按"语种"估算**——`请求项 v2.1` 是 3 个宽字符 + 5 个窄字符，漏掉 `2` `.` `1` 就会把盒子定窄 3 个字位。
- **技术值保持拉丁**：端口、协议、命令、参数、URL、字段名保持等宽拉丁字形（字体栈末尾兜底 `ui-monospace, Menlo, Consolas, monospace`）；不要翻译技术值。
- **小号轨道（7–9px）不放汉字**。eyebrow、箭头标签、图例文字若必须用中文，切成 12px 无衬线、去掉大写字距（letter-spacing）。汉字 sublabel 同理提升到 12px。
- matplotlib 侧：中文标签字号 ≥10pt（figstyle 默认 10–11 已合规）；标题讲结论不讲名词。

## 4. 网格与尺寸

- **4px 网格（硬规则）**：节点原点、宽、高、间距、内边距全部是 4 的倍数。
- 推荐值：宽/高 80、96、112、120、128、140、160、180、200、240；间距 20、24、32、40、48；内边距 8、12、16；圆角 4（小标签）、6（节点框）、8（容器）。
- 不在网格上的：字号、描边宽（0.8/1/1.2）、文本基线、箭头标记、数据驱动位置、保 1px 描边清晰的 `.5` 偏移。

## 5. 连线六规则（手写 SVG 强制）

非共轴连接一律**正交圆角**，不允许斜线。两折肘形路径（right+down，mid = (x1+x2)/2，r=8）：

```svg
<path d="M x1,y1 H mid-8 Q mid,y1 mid,y1+8 V y2-8 Q mid,y2 mid+8,y2 H x2"
      fill="none" stroke="#5f6368" stroke-width="1.2" marker-end="url(#m)"/>
```

1. **正交圆角**。禁止对角斜线；端点垂直贴边、距角 ≥8px（贴到圆角上会显得线从角上长出）。水平段不得从顶/底边出发、垂直段不得从左/右边出发（贴着边框会被节点填充盖住）。目标在上下方时走单折 L 形：从侧面出、横走、一次转弯、垂直到目标上/下边。
2. **标签与线间隙 6–10px**。箭头标签用不透明掩码矩形垫底，掩码底边与线保持 6–10px 可见间隙，绝不压线；竖线标签放线侧边，同样留间隙。
3. **连线不重叠**。两线不共路径、不长时间并排重叠；必须交叉时画 **hop**（本线为次要线）：

```svg
<!-- 水平线在 x=cx 处跨过竖线：半径 8 的半圆小桥 -->
<path d="M x1,y H cx-8 a 8,8 0 0,1 16,0 H x2" fill="none" stroke="#5f6368" marker-end="url(#m)"/>
```

   同向平行线间距全程 ≥12px；线一叠，图就废，重排或拆图。
4. **共边扇出**。N 条连线进出同一节点同一条边时，每条一个独立 attach 点，间距 ≥12px（小盒 ≥8px）；第 k 点距边起始角的偏移 = `L * k / (N + 1)`。禁止两线共用一点。
5. **不穿盒**。连线不得穿过非源、非端的节点框；几何上不可避免时（如横穿的层条）该段用 `stroke-dasharray="4,3"` 虚线并只在可见端标标签，箭头只落在真终点。存疑就绕。
6. **掩码不压后绘节点**。绘制顺序为 背景 → 区域 → 连线 → 标签 → 节点；标签掩码不得与后绘制的节点框重叠（会被节点填充盖住，文字变成贴在边框上的碎片）。标签放在连线的开阔段上。

虚线（`stroke-dasharray="4,3"`）只表达语义（可选、返回、异步、透传），同样遵守上述全部路由规则。

## 6. 语义模式 → 图型选择（技术报告常用）

行为、状态、风险是重点时，先选**语义模式**再定图型；否则直接按内容选图型。一图一主模式，两套机制都要说就拆图。

| 读者要理解…… | 语义模式 | 首选图型 |
|--------------|----------|----------|
| 多来源汇入有限容量（队列、等待、反压） | fan-in 队列/瓶颈 | 数据流 |
| 各阶段重复同样的语义槽（输入/门控/输出） | 阶段框架 | 流程 |
| 一个主体历经阶段、等待、重试、终止 | 生命周期相位图 | 状态机 |
| 系统分解为可独立引用的块 | 可追溯分解 | 树 |
| 哪些路径允许跨信任边界、哪些被阻断 | 受控通路（secure paved road） | 架构 |
| 防线层层补偿、残余风险逐层收窄 | 补偿安全层 | 层叠 |
| 规则逐条判定、在哪一条首次分歧 | 成对策略轨迹 | 流程图 |

模式自身的复杂度预算可以更严，不得放松图型预算：状态类 ≤9 态 ≤10 转移；受控通路 ≤3 信任区 ≤8 组件 ≤2 禁止路径；补偿层 3–5 层、一条主风险线。

## 7. 手写 SVG 要点

- 画布：固定 `viewBox`；背景 rect 垫底；`role="img"` + `aria-label`。
- `<defs>` 三个箭头标记（默认 muted、焦点 accent、外部 link），`refX` 让箭头尖贴住线端。
- 绘制顺序即 z 序：背景 → 区域容器（层级/信任区的浅色大框）→ 连线 → 标签 → 节点。**先画线后画盒**，线在盒后收口。
- 节点框模式：名称（12px+、600 字重、sans）+ 技术 sublabel（等宽、muted/soft）；标签衬 12–14px 高的 paper 色掩码。
- 区域容器：填充 ink @2–3% 浅灰，描边 ink @10% 细线；容器标签用 soft 色小字放在容器内上方，与第一个节点留 ≥16px。
- 图例放画布底部横条（细分割线上方），不进图内。
- 自检：`python3 skills/document/scripts/check_svg_geometry.py <fig>.svg` 检查对角线、贴角端点、节点重叠、穿盒、CJK 字号地板。

## 8. 预输出检查（Taste Gate）

**图型适配**
- [ ] 这段内容真的需要图吗？（表格/段落能做就不画）
- [ ] 适用时先定了语义模式，再选图型？
- [ ] 信息超过预算时已拆成两图？

**删除测试**
- [ ] 有可删的节点吗（删掉读者仍能理解）？
- [ ] 有可合并的节点吗（两者总是一起出现）？
- [ ] 有可删的箭头吗（关系从布局已显而易见）？
- [ ] 有可删的标签吗（颜色/形状已经说明）？

**信号**
- [ ] 焦点色 ≤2 处？多余的降为 ink/muted 系。
- [ ] 图例只覆盖用到的类型、无多余项？
- [ ] 在复杂度预算内（≤9 主节点、≤12 连线）？

**技术**
- [ ] 连线六规则逐条过（或 `check_svg_geometry.py` 通过）？
- [ ] 4px 网格：节点原点/尺寸/间距/内边距？
- [ ] 汉字 ≥12px、技术值保留等宽拉丁？
- [ ] 标签掩码离线 6–10px、不压节点？
- [ ] `role="img"` + `aria-label` 完整？

## 9. 与生成式工具的分工

| 图形 | 工具 | 套用的规则 |
|------|------|------------|
| 数据图（柱/线/散点/热力） | matplotlib + figstyle | §2 配色纪律、CJK 字号；几何由工具保证 |
| 流程/依赖/结构（常规） | graphviz dot | §2 配色纪律、节点数预算；路由由 dot 保证 |
| 机制图/架构概念图/对照矩阵（需要精确控制） | 手写 SVG | 本文件全部规则，尤其是 §3 §4 §5 |

手写 SVG 的门槛是有理由的：只有当图的形状本身承载论证（机制对齐、时序衔接、边界关系）时才手写；能用 dot 自动布局的一律用 dot。
